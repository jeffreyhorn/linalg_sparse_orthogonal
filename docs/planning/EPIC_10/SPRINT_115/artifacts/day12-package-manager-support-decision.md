# Day 12: Package-Manager Support Decision

## Purpose

Day 12 decides whether Sprint 115 should add package-manager support or keep
package-manager distribution as future product work. The decision must not
confuse dependency installation commands with a supported package recipe for
this library.

## Inventory

| Reference class | Current state | Interpretation |
|---|---|---|
| Homebrew | Used for developer dependencies such as GCC, LLVM, libomp, lcov, gcovr, and cppcheck. | Dependency setup only; no library formula. |
| apt/dnf | Used for Linux developer dependencies such as compilers, `pkg-config`, lcov, and bc. | Dependency setup only; no distro package recipe. |
| Windows package managers | No Chocolatey, winget, vcpkg, or MSYS2 package recipe is present. | No Windows package-manager support. |
| `pkg-config` | Installed metadata generated by Make/CMake install paths. | Installed-consumer metadata, not a package-manager recipe. |
| `find_package(Sparse)` | Installed CMake package metadata and downstream consumer path. | Installed-consumer metadata, not package-manager support. |
| `DESTDIR` staged install | Supported by Makefile install. | Useful packaging primitive, not a shipped package recipe. |

## Decision

Sprint 115 does not add package-manager support.

Package-manager distribution remains future product work. The maintained
package surface remains the static-first install/export story documented in
`INSTALL.md`: Make install, CMake install/export, `pkg-config`, and
`find_package(Sparse)`.

## Rationale

Adding package-manager support requires more than a recipe file. It would make
the project responsible for source integrity, dependency mapping, install
layout, consumer proof, version policy, platform support, and ongoing recipe
maintenance. Sprint 115 has not added that proof, and the current static-first
contract intentionally avoids shared-library and dynamic ABI promises that many
package-manager users would otherwise assume.

## Candidate Recipe Requirements

### Homebrew Formula

Required before claiming Homebrew support:

1. Formula that builds from a tagged release archive.
2. Dependency declarations for CMake or Make and optional OpenMP behavior.
3. Static-first install proof.
4. Formula test block that compiles and runs a downstream consumer using
   `pkg-config` or `find_package(Sparse)`.
5. Documentation that does not imply dylib, dynamic ABI, or macOS full
   install/export parity unless those proofs exist.

### vcpkg Port

Required before claiming vcpkg support:

1. `vcpkg.json` and portfile with static-first CMake install behavior.
2. Triplet coverage decision for Windows, Linux, and macOS.
3. Downstream `find_package(Sparse)` consumer proof.
4. Explicit Windows static `.lib` expectation and no DLL claim unless proven.
5. CI or reproducible local evidence for the claimed triplets.

### Linux Distro Package

Required before claiming distro packaging:

1. Debian/Fedora packaging metadata or equivalent recipe.
2. License, source archive, version, and dependency mapping.
3. Installed headers, static archive, CMake package, and `pkg-config` proof.
4. Downstream compile/link/run smoke test.
5. Documentation that separates distro package support from source-tree
   install support.

### Windows Package Manager

Required before claiming Chocolatey, winget, or MSYS2 support:

1. Package metadata and install layout for the selected manager.
2. MSVC static library and CMake package consumption proof.
3. Clear statement that Windows does not claim Makefile or `pkg-config` parity
   unless separately proven.
4. Runtime-loader proof if any DLL/shared-library support is introduced.

### Conan or Spack

Required before claiming Conan or Spack support:

1. Recipe/package definition matching the static-first support tier.
2. Dependency/options model for OpenMP and mutex settings.
3. Downstream consumer build/run proof.
4. Version compatibility wording aligned with exact-version package behavior.

## Non-Claims Preserved

Day 12 does not claim:

- Homebrew formula support;
- vcpkg port support;
- distro package support;
- Chocolatey, winget, or MSYS2 support;
- Conan or Spack support;
- package-manager shared-library support;
- dynamic ABI compatibility;
- package-manager runtime-loader behavior.

## Sprint 116 Adoption QA Handoff

Sprint 116 adoption QA should treat package-manager support as absent unless a
future sprint lands an actual recipe plus validation. Adoption docs can point
users to the maintained static install/export paths, but should not advertise
package-manager installation commands for this library.

## Validation

Day 12 is documentation-only. No CMake, Makefile, workflow, source, header, or
package metadata changes were made.
