## What Went Well

1. **The sprint made a clear product decision before changing publication
   mechanics.** Sprint 179 did not drift into a partial hosted or artifact
   model. It first evaluated the realistic options and then selected a
   strengthened local-only status.

2. **The selected decision is enforceable.** The local-only guard now checks
   ignore rules, tracked/staged/non-ignored generated output, Doxyfile input
   and output settings, required docs wording, and workflow references to
   generated API output paths.

3. **The source of truth is easier to explain.** README, API reference, and
   maintainer guidance now consistently point to `docs/api_reference.md` plus
   checked-in public headers as the source-controlled API documentation path.

4. **The generated HTML role is bounded.** `docs/api/html/` is documented as a
   checkout-local maintainer convenience view regenerated by
   `make api-docs-freshness`, not hosted documentation or release evidence.

5. **Validation is concise.** `make api-docs-freshness` gives maintainers one
   command that regenerates Doxygen output, verifies configured public-header
   coverage, and runs the strengthened local-only guard.

6. **Rejected paths are visible.** The artifacts and docs explicitly reject
   hosted publication, retained CI artifacts, and committed generated output for
   this sprint rather than leaving those paths ambiguous.

## What Didn't Go Well

1. **The final decision is still a non-publication decision.** This closes the
   ambiguity gap, but it does not improve user access to generated HTML outside
   a local checkout.

2. **The generated API surface remains narrow.** The Doxygen input set remains
   declaration-level public headers under `include/`; examples, tutorials,
   cookbook content, maintainer docs, and generated install headers are not
   part of the generated HTML surface.

3. **The guard is intentionally string based.** That is acceptable for the
   selected local-only status, but a future hosted or artifact-published path
   would need more structured workflow and publication metadata checks.

4. **Doxygen warnings are not made fatal.** Sprint 179 observed clean selected
   runs, but it did not add `WARN_AS_ERROR` or a broader warning policy.

5. **Documentation wording now participates in validation.** That is useful
   for claim governance, but maintainers must update the guard strings together
   with future wording changes.

## Closed Claim

Sprint 179 closes this Epic 16 generated API claim:

Generated API HTML has a deliberate strengthened local-only product status.
The maintained supported API documentation path is `docs/api_reference.md`
plus checked-in public headers under `include/`, while local generated HTML is
regenerated and checked with `make api-docs-freshness`.

This does not claim hosted generated API documentation, retained CI generated
API artifacts, committed generated output, generated HTML release evidence, or
generated documentation coverage beyond the configured Doxygen public-header
input set.

## Follow-Up Risks

1. **Hosted publication remains unresolved by design.** A future hosted path
   needs an explicit product decision, workflow owner, deployment guard,
   freshness metadata, and public claim wording.

2. **Retained artifact publication remains unsupported.** A future artifact
   path needs upload scope, retention policy, fail-closed checks, and support
   tier wording.

3. **Committed generated output remains rejected.** Reversing this would need
   `.gitignore`, staging, repository-size, and review-noise decisions.

4. **Workflow validation must grow if publication grows.** The current guard is
   fit for local-only rejection of generated API output path references, not
   for proving a hosted publication lane.

5. **Generated narrative coverage remains separate.** Tutorials, cookbook
   pages, examples, and maintainer docs remain source-controlled narrative
   surfaces rather than Doxygen inputs.
