# Sprint 163 Day 8 Gate Classification And Publication Policy

## Purpose

Day 8 converts the completed Day 6 and Day 7 report behavior into a publication
policy. The policy distinguishes hard timing gates from threshold-free reports,
generated local-only artifacts, advisory normalized-index rows, supplemental
rows, hosted-only evidence, and deferred rows.

## Publication Eligibility Policy

Source-controlled documentation may publish:

- the selected command names;
- row families and row meanings;
- schema fields and methodology requirements;
- regeneration instructions;
- non-claim and caveat wording;
- validation command records;
- deferred-row rationale.

Source-controlled documentation must not publish as proof:

- generated timing CSVs;
- generated benchmark `index.tsv` rows;
- generated sentinel `sentinels.tsv` rows;
- generated `wall_check.txt` output;
- generated normalized report-index rows;
- local CI-equivalent timing copied from a workstation;
- skipped rows as passing evidence.

Generated artifacts remain under ignored `build/` paths:

- `build/bench-reports/canonical/`
- `build/bench-reports/sentinels/`
- `build/report-index/`

If a future sprint wants checked-in example rows, it must define a separate
fixture, timestamp, freshness, and claim-boundary contract.

## Local-Only Versus Hosted Evidence

Local-only evidence:

- is generated on the current workstation or local CI-like environment;
- may support local debugging, before/after comparison, and review inspection;
- must stay tied to command, commit, branch, platform, compiler, build mode,
  thread setting, fixture/workload, and backend context;
- cannot be cited as hosted CI proof.

Hosted-only evidence:

- must be generated by the named hosted workflow or job;
- may cite the runner context and uploaded artifact or log;
- cannot be inferred from local generated artifacts;
- must preserve the same non-portability and non-superiority caveats.

## CI And Runtime Budget Policy

- `make bench-canonical-report` is eligible for local validation and optional
  CI artifact capture if the CI lane explicitly owns its runtime budget.
- `make performance-sentinels` is eligible for local validation and optional
  CI artifact capture if S5 wall-check runtime is acceptable for that lane.
- `make bench`, broad benchmark sweeps, and exploratory benchmark commands are
  not selected for Sprint 163 mandatory publication validation.
- Timing-sensitive CI failures should be handled as local-gate failures only
  when the lane explicitly owns the baseline and threshold.
- A slow or flaky timing environment should produce a documented skip, defer,
  or failure state rather than weaker pass wording.

## Row-State Policy

| State | Policy |
| --- | --- |
| `pass` | Valid only for thresholded local gate rows such as S5. Must keep baseline and threshold visible. |
| `fail` | Valid only for thresholded local gate rows or command failures. Preserve nonzero failure behavior. |
| `report` | Valid for threshold-free sentinel context rows. Not pass/fail evidence. |
| `measurement` | Valid for canonical threshold-free benchmark rows. Not pass/fail evidence. |
| `advisory` | Valid for normalized/report-index navigation rows. Not release proof. |
| `skip` | Scope signal caused by missing binary, fixture, baseline, opt-in, or unavailable environment. Not passing evidence. |
| `defer` | Explicit decision to postpone a row or surface. Not evidence. |
| `missing` | Blocks publication of that row until regenerated or deferred. |
| `stale` | Blocks publication until regenerated or explicitly scoped out. |
| `malformed` | Blocks publication and requires script/schema repair. |

## Variance, Drift, And Flaky Timing Policy

- Rows with `variance=not_recorded` must not be described as statistical
  summaries.
- Rows with `warmup=not_recorded` must not imply warmup behavior.
- Single configured-repeat rows may support local before/after inspection only
  when command, environment, fixture, and build context match.
- Drift across machines, compilers, OpenMP settings, or backend settings is
  methodology context, not product performance proof.
- Flaky local timing should be treated as a gate/measurement quality issue,
  not as permission to weaken a threshold or publish broader claims.
- Any new threshold requires a fresh local-baseline and machine-class policy.

## Unsupported Citation Policy

Do not cite Sprint 163 selected rows as:

- portable performance guarantees;
- state-of-the-art evidence;
- broad platform parity evidence;
- package, install, package-manager, shared-library, dynamic ABI, or
  runtime-loader evidence;
- external-library parity evidence;
- OpenMP speedup evidence;
- backend superiority evidence;
- broad release benchmark proof.

Do cite them as:

- methodology-bound local benchmark snapshots;
- the existing local S5 wall-check gate;
- threshold-free S2/S3 backend-context reports;
- generated local artifacts that can be regenerated from maintained commands.

- hard-gate versus threshold-free semantics;
- non-superiority caveats.

- hosted-only evidence caveats;

## Completion Check

- Hard gates are separated from threshold-free methodology reports.
- Publication eligibility is explicit.
- Local-only evidence cannot be cited as hosted proof.
- Stale, skip, defer, malformed, failed, advisory, and local-only semantics are
  documented before public docs are updated.
