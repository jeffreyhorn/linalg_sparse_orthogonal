# Sprint 138 Day 7 - Oracle Schema Implementation

## Purpose

Day 7 implements the initial corpus oracle schema surface. It adds the
source-controlled oracle field documentation, updates first-lane expected-result
rows to match the Day 6 design, and adds a lightweight validation helper for
maintained corpus TSV skeletons.

This implementation does not add a generator, observed oracle rows, report
command, solver tests, generated outputs, optional external data, or public
claim updates.

## Mechanical Validation

The new validator runs as:

```sh
python3 scripts/validate_corpus_schema.py
```

The validation currently checks:

1. TSV files are non-empty and every row has the same width as its header.
2. Required fixture, generator, optional-data, and expected-result fields are
   present.
3. Fixture keys are unique and generated fixtures reference known generator
   keys.
4. Expected-result rows reference known fixture keys.
5. Selected enum fields use known values.
6. Numeric tolerance kinds carry a tolerance value; status-only and
   not-applicable tolerance kinds do not.
7. Expected-result skeleton statuses are placeholders, not pass evidence.
