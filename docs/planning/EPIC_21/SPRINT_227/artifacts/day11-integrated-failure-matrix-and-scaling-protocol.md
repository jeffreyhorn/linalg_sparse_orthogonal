## Pinned workload identities

The benchmark constructs A and B before the clock, times exactly one `sparse_add(A, B, 1, 1,
&C)`, then checks every logical cell of A, B, and C. It also checks dimensions and exact `nnz`.
The input patterns are disjoint, so emitted `nnz` and maximum output row width are exact and the
timed operation isolates sorted-output construction rather than cancellation policy.

| Fixture | Stable workload ID | Shape | A/B/output `nnz` | Maximum output row width | Purpose |
| --- | --- | --- | --- | --- | --- |
| Wide row | `s227-add-wide-r1-c4096-v1` | 1 x 4096 | 2048 / 2048 / 4096 | 4096 | Exposes construction cost for one long sorted row. |
| Varied rows | `s227-add-varied-r64-c1024-v1` | 64 x 1024 | 4608 / 4608 / 9216 | 256 | Exercises deterministic row widths 32 through 256. |
| Narrow-row control | `s227-add-narrow-r1024-c64-v1` | 1024 x 64 | 4096 / 4096 / 8192 | 8 | Separates many short rows from the long-row case at similar output scale. |

Values are deterministic finite signed binary fractions. Column identities are generated by the
checked-in benchmark rather than a runtime seed. A nonzero exit, malformed CSV row, identity
mismatch, incorrect `nnz`, nonfinite value, or input mutation invalidates that invocation.

## Frozen Day 12 collection protocol

### Compared revisions and build route

- Baseline library source: `fcdeaaee856821e8c801d805c63b5fd40eb89b2f`, the Sprint 227 base.
- Candidate library source: the exact Day 12 Sprint 227 working tree after quality checks.
- Driver: the same checked-in candidate `benchmarks/bench_add.c` is compiled separately against
  each library. This avoids comparing different clocks, fixtures, or validators.
- Toolchain: `/usr/bin/clang`, C11, `-O2`, `SPARSE_IDX_BITS=32`, OpenMP disabled, sanitizers and
  coverage disabled, static library, and `-lm`. Baseline and candidate must use the same compiler
  path/version, SDK, flags, and benchmark source bytes.
- Build trees and executables are separate. No object, generated header, archive, or executable
  may be shared between variants.

Before collection, retain the source commit, `git status --short`, binary diff SHA-256, relevant
source SHA-256 values, benchmark-source SHA-256, archive SHA-256, executable SHA-256, compiler
path/version, complete compile/link commands, and index-width proof. A mismatch invalidates the
collection rather than being repaired after seeing results.

### Host controls and ordering

- Use one otherwise-idle macOS host and one uninterrupted session on AC power.
- Set `OMP_NUM_THREADS=1`, `LC_ALL=C`, and `TZ=UTC`; run serially with no concurrent benchmark.
- Record host model, CPU, physical/logical core counts, memory, OS/build, power source, and the
  start/end UTC timestamps. Do not claim CPU-frequency or thermal isolation unless measured.
- Run two unrecorded correctness-qualified warmups per fixture and variant.
- Run ten numbered independent-process baseline/candidate pairs per fixture. Odd pairs use
  baseline then candidate; even pairs use candidate then baseline. Complete one pair before the
  next and retain the declared order.
- A failed or interrupted invocation invalidates its pair. Rerun the entire collection before
  inspecting aggregate results; do not selectively replace samples or delete outliers.

Each invocation has a 30-second command timeout. The complete collection has a 15-minute cap so
receipt and raw-output finalization cannot be displaced by retries. Hitting either cap invalidates
the collection.

### Metrics and retained evidence

- Primary time metric: benchmark-emitted `elapsed_ms`, covering only the `sparse_add` call.
- Report, per fixture and variant, all ten values plus median, minimum, maximum, and IQR. Also
  report each paired candidate/baseline ratio and its median. No hypothesis-test or universal
  speed claim is authorized.
- Memory context: invoke each process through `/usr/bin/time -l` and retain maximum resident set
  size and peak memory footprint where emitted. These are whole-process observations including
  fixture setup and validation, not isolated add-allocation measurements.
- Retain raw stdout, stderr, timing stderr, exit status, invocation argv, pair/order metadata, and
  SHA-256 for every file. Retain the environment/build receipt and a manifest covering every raw
  file. Raw output is immutable after hashing.

The Day 12 report must reconcile every CSV identity and count with the table above before any
aggregate is calculated. It must publish contradictory or noisy results and preserve this
protocol's invalidation rules.

## Claim boundary

Accepted evidence may describe only these three selected addition workloads, on the recorded
host, compiler, and exact source pair. It may discuss the timed sorted-output construction call
and whole-process memory context separately. It does not establish whole-library performance,
portable scaling, allocator-independent memory improvement, superiority to another library, or
state-of-the-art performance.
