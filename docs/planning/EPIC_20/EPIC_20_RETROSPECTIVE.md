# Epic 20 Retrospective

**Epic:** 20 - Selected Numerical, Package, Evidence, Platform and Release Gaps

**Sprints:** 217–226
**Status:** Selected numerical, algorithm, static-package, workflow and evidence-validator work landed. The intended exact static source-release candidate and several external-evidence outcomes remain **blocked**. No release-ready or state-of-the-art claim is earned.

## Objective And Evidence Rule

The [project plan](PROJECT_PLAN.md) allocated ten 14-day sprints and 1,400 estimated hours, below its 1,680-hour ceiling. It deliberately favored closing selected gaps over partial progress across every limitation. The estimates were planning capacity, not measured labor. The [Sprint 226 completion reconciliation](SPRINT_226/artifacts/day13-epic20-completion-reconciliation.md) accounts for each planned item group; its [validation and claim ledger](SPRINT_226/artifacts/day13-validation-and-claim-ledger.md) supplies provenance, scope, owner roles and next actions. The [Sprint 226 retrospective](SPRINT_226/RETROSPECTIVE.md) and [final handoff](SPRINT_226/artifacts/day14-final-epic20-closeout-and-handoff.md) record the closeout decision.

Here, **closed** means the bounded selected output was implemented and evidenced. **Blocked** means a planned product or release acceptance condition still lacks mandatory evidence or approval. **Deferred** means deliberately outside Epic 20's funded scope. A local implementation, synthetic validator pass, historical hosted receipt or blocked run cannot be counted as the missing product result. The Sprint 226 handoff is complete as documentation, while the release-candidate outcome it describes remains blocked.

A passed schema, local numerical comparison and independent baseline claim are three different states.

## What Went Well And What Did Not

**Worked:** the ten-sprint sequence gave each selected gap a testable owner; strict provenance prevented a misleading CHOLMOD or source-release promotion; width-aware installed consumers and corrected first-use instructions gave users a concrete static route; selected Windows rows were supported by real artifacts rather than workflow registration alone; and the timing gate preserved negative evidence without changing its policy after the baseline failed.

**Did not close:** Sprint 222 lacked complete runtime/BLAS and rights provenance; Sprint 225 could not establish a compatible accepted baseline; Sprint 226 could not select a clean reviewed candidate or obtain named approvals. The historical Linux base CMake run was interrupted at CTest 32/63, and the local optional Homebrew provider aggregate stopped during a dependency build. PR #250's later successful Linux rerun resolves that PR-head CI interruption but does not retroactively make the base-run receipt complete or authorize a release. The archive reproducibility exercise had to remain exploratory because the package text changed afterward.

The planning lesson is to secure release owners, a version/changelog decision and a clean candidate identity before investing in candidate-labeled archive/platform work. The evidence lesson is to retain raw hosted artifacts and their hashes before later source edits or reruns, and to distinguish a fail-closed validator from an accepted real-world result. The [Sprint 226 handoff](SPRINT_226/artifacts/day14-final-epic20-closeout-and-handoff.md#residual-handoff-with-acceptance-gates) turns both lessons into acceptance gates.

## Capability And State-Of-The-Art Assessment

The project has useful selected numerical diagnostics, a more efficient matmul output-linking path, a safer static installed width contract, structured documentation publication guards, and selected hosted Cholesky/QR comparison rows. It has **not** earned a general state-of-the-art sparse linear algebra claim. One tiny local CHOLMOD fixture without validator-accepted provenance or rights approval does not establish independent solver parity. One selected local matmul profile and an unmeasured canonical timing gate do not establish portable performance superiority. The static package does not establish shared/dynamic ABI, binary/provider distribution, cross-version compatibility or a tagged release.

Generated API HTML remains local-only. Windows Make/pkg-config execution parity, broad 64-bit algorithm coverage, broad Windows solver coverage and generalized external-baseline comparisons were outside the funded selected scope. These are **deferred capabilities**, not implicit Epic 20 successes. The [claim ledger](SPRINT_226/artifacts/day13-validation-and-claim-ledger.md) names exact supported wording for every retained area.
