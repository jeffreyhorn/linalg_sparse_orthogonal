# Day 8 Downstream Consumer Proof

## Purpose

Day 8 consolidates the downstream consumer evidence from the Day 6 Make
install proof and the Day 7 CMake install/export proof. The goal is to confirm
that the selected static-first package tier has installed public-header
consumer coverage without requiring private headers, source-tree-only package
paths, or unsupported shared-library / ABI claims.

## Additional Consumer Decision

No extra Day 8 consumer source was added.

Reason:

- Day 6 already proves pkg-config compile/link/run for a generated consumer and
  the maintained example source.
- Day 7 already proves installed CMake configure/build/run for
  `examples/cmake_example/`.
- The selected support tier is static-first package consumption, not broad
  installed coverage for every local teaching example.
- Compressed-input and Matrix Market workflows remain covered by local examples
  and Sprint 111 docs; adding them to installed package proof would broaden
  Day 8 scope without changing the package-support claim.

## Supported Claim

Day 8 supports this bounded claim:

> The selected static-first package tier has downstream consumer proof through
> both installed pkg-config flags and installed CMake `find_package(Sparse)`
> metadata, using public installed headers only.

## Non-Claims

Day 8 does not claim:

- shared-library package support;
- dynamic ABI stability;
- installed proof for every local teaching example;
- Windows separate install-validation support;
- macOS reviewed install/export parity;
- package support beyond the static-first surfaces validated by Days 6 and 7.

## Completion Criteria Status

- At least one downstream consumer proves the selected package tier; both
  pkg-config and CMake consumers passed.
- Private implementation headers are not required by consumers.
- Documentation update needs are concrete: no Day 8 docs change is required,
  but Day 12 should preserve the existing bounded install-consumer wording.
