# Day 2: Width Contract And Failure Design

**Date:** 2026-10-24
**Scope:** Sprint 219 item 219.1, final 10 of 20 planned hours
**Source revision:** `145b5a5a21dbb5191d5d1e1e2550b80c98819861`
**Status:** Design only; no 64-bit package or mismatch rejection is implemented yet.

The [Day 1 inventory](day1-public-abi-width-inventory.md) establishes that
`idx_t` crosses public scalar, array, struct, and callback boundaries. A
consumer-local `_Static_assert` is insufficient: a forced 64-bit consumer
currently links to a 32-bit archive. This design binds a package's generated
header, exported build metadata, and archive query before such use.

## Selection And Build Identity

| Build route | Supported selector | Invalid selector | Clean-build rule |
| --- | --- | --- | --- |
| CMake | `-DSPARSE_IDX_BITS=32` or `64`; default `32` | Reject at configure with `SPARSE_IDX_BITS must be 32 or 64` (including empty, nonnumeric, zero, and other integers). | Use independent build trees for 32 and 64. A reconfigure in an existing tree must rebuild every width-dependent object and generated header, or fail before build if that cannot be guaranteed. |
| Make | `make SPARSE_IDX_BITS=32` or `64`; default `32` | Reject during Makefile parsing, before compiling or installing, with the same allowed-value message. | Use separate `BUILDDIR` values. Store the selected width in each build tree and reject an opposite-width reuse before any old object/archive can satisfy a target. `make clean` can then reset that tree. |

The selector must drive **all** library objects, tests, examples, benchmarks,
generated package metadata, and installation, rather than relying on ambient
`CFLAGS`. A command-line override in `CFLAGS`/`CMAKE_C_FLAGS` that changes the
effective width must not produce a package whose generated identity disagrees
with its archive. Build-time identity tests must compare the compiled
`sizeof(idx_t) * CHAR_BIT` with `sparse_idx_bits()` in each clean tree.
Generated version/width metadata must be a dependency of width-sensitive
objects. The static install validator must reject a package assembled from
stale or mixed files before it is offered to downstream tests.

## One Installed Identity

Generate one numeric `SPARSE_BUILT_IDX_BITS` value (`32` or `64`) into
`sparse_version.h` from the validated build selector. Both Make and CMake
install this generated header next to the source headers. It is the package's
compile-time width identity, not a consumer preference and not an ABI-version
promise. Make's template substitution and CMake's `configure_file` must use
the same value. Do not edit the source-tree headers per build.

`sparse_types.h` should default an unspecified `SPARSE_IDX_BITS` to
`SPARSE_BUILT_IDX_BITS`, then issue a compile-time `#error` when an explicit
effective `SPARSE_IDX_BITS` differs. It should also reject a missing or
unsupported built value, then retain its existing `idx_t` size assertion.
This makes direct use of a *complete installed header pair* select the
package width even without a helper tool. A generated header from a
different prefix is not interchangeable with `sparse_types.h` from this one.

The exported `Sparse::sparse_lu_ortho` target must publish
`SPARSE_PACKAGE_IDX_BITS=N` as an `INTERFACE_COMPILE_DEFINITIONS` usage
requirement. The `sparse.pc` file generated by **both** build systems must
emit `-DSPARSE_PACKAGE_IDX_BITS=N` in `Cflags`, preserving the static link
flags and relocatable CMake target paths. The public header must reject an
effective `SPARSE_PACKAGE_IDX_BITS` that differs from
`SPARSE_BUILT_IDX_BITS`. This separate package macro advertises the width
without overwriting a consumer's explicit `SPARSE_IDX_BITS`. The
installed-contract validator must compare the header value, CMake usage
requirement (where present), pkg-config flag, and archive's
`sparse_idx_bits()` result. A width field missing, duplicated, unsupported,
or inconsistent with the archive is an invalid package.

Keeping the package and consumer macros distinct makes a single explicit
conflicting consumer `-DSPARSE_IDX_BITS=M` fail regardless of whether
pkg-config/CMake flags appear before or after it. Duplicate definitions of
**the same** macro cannot reveal every earlier value to the C preprocessor:
a compiler may replace the first definition with the last and only warn.
The generated-header comparison therefore checks the **effective** values
of both macros after all flags, in both option orders. If either is wrong,
compilation fails; if both equal the installed value, `idx_t` has the right
width even if an earlier contradictory flag was masked. CMake tests should
exercise explicit consumer definitions through target properties and
`CMAKE_C_FLAGS`; pkg-config tests should exercise both flag orders. The
contract must not claim to diagnose a same-name contradiction that the
compiler has already overwritten with the correct final value.

## Archive Check Before Unsafe Use

The archive exports `sparse_idx_bits()` with no `idx_t` argument, so it is
safe to call before crossing an index-bearing ABI boundary. The maintained
installed-consumer fixtures should call a reusable check at the beginning of
`main`, before matrix creation, dimensions, index arrays, public structs,
callbacks, or solver calls. Conceptually:

```c
if (sizeof(idx_t) * CHAR_BIT != SPARSE_BUILT_IDX_BITS ||
    sparse_idx_bits() != SPARSE_BUILT_IDX_BITS) {
    fprintf(stderr, "sparse index-width mismatch: header=%d archive=%zu\n",
            SPARSE_BUILT_IDX_BITS, sparse_idx_bits());
    return EXIT_FAILURE;
}
```

The implementation should query once and report that value, make the check
unconditional, and use no index-bearing API on failure. A positive fixture
must continue to a real library call so an accidental early exit cannot
pass. Tests must prove that a swapped archive fails in this check before the
unsafe call. Build/package validation should make ordinary mismatched
prefixes fail earlier; the runtime check covers a library file swapped after
metadata generation or an explicit mixed include/archive command.

No portable automatic link-time guard exists for the current width-neutral C
symbols without changing the public calling surface or forcing a reference
from every entry point. This sprint therefore chooses a **compile-time
header guard plus an executable pre-use archive check**, not a link-time
symbol change. Raw manual linking that bypasses the package metadata and
omits the check is unsupported and may still invoke an unsafe API. Likewise,
the check is not a claim about cross-version ABI, shared libraries, scalar
types, or correctness of every 64-bit algorithm.

## Frozen Consumer Matrix

`H` denotes the installed generated-header width, `A` the actual archive
width, and `F` the consumer's effective `SPARSE_IDX_BITS`. Each negative
fixture must prove that no index-bearing API ran; tests must capture the
expected diagnostic, not merely a nonzero exit.

| Case | Route / package state | Expected phase and diagnostic |
| --- | --- | --- |
| P1 | Make 32 and Make 64, separate prefixes, pkg-config consumer with emitted flags | Compile, link, width check, then representative API call pass; `H=F=A`. |
| P2 | CMake 32 and CMake 64, separate prefixes, `find_package` target consumer | Configure, compile, link, width check, then representative API call pass; `H=F=A`. |
| P3 | CMake-installed 32/64 package consumed through its `sparse.pc` | Same positive sequence; verifies cross-route metadata parity. |
| P4 | Direct include of a complete installed header pair, no explicit width macro | Compile defaults `F=H`; width check and safe call pass for both widths. |
| N1 | Build selector `0`, `16`, `128`, empty, or nonnumeric | CMake configure or Make parse fails with allowed-values diagnostic; no archive is installed. |
| N2 | Explicit `F=64` against 32-bit headers, or `F=32` against 64-bit headers, through either consumer route | Compile fails with header/package width mismatch before link or use. Distinct package macro prevents an exported flag from masking the override. Test flag order and CMake target-property/global-flag variants. |
| N3 | Duplicate `-D` flags for the same macro whose final effective value differs from `H` | Compile fails with the same header mismatch. If the final value equals `H`, compile may pass; log the masked conflict as a limitation, but the resulting typedef is not mismatched. |
| N4 | Missing, duplicate, unsupported, or wrong width in `sparse.pc`/CMake export/generated header | Static validator fails with a field-specific package identity error; no downstream executable is used. |
| N5 | Archive replaced by opposite-width archive while headers and metadata remain internally consistent | Validator rejects `A!=H`; an intentionally bypassed validator still reaches the consumer's pre-use check, which fails with header/archive mismatch. |
| N6 | Header from one prefix with archive from another, both otherwise valid | Compile rejects if generated-header `H` disagrees with effective `F`; if it does not, pre-use check rejects `A!=H`. Never execute an index-bearing call. |
| N7 | Reuse Make `BUILDDIR` for the other width without cleaning | Make refuses before reusing objects/archive, naming old and requested widths. A clean or separate tree succeeds. |
| N8 | Reconfigure CMake build tree to the other width, or point a cached consumer at a different prefix | Library tree rebuilds all width-dependent objects/header or rejects reconfigure; consumer compile guard, package validator, or pre-use query rejects stale/mixed output. |

The fixtures must isolate include, library, and pkg-config lookup from host
installations. For a negative archive-link case, use an absolute archive path
instead of relying on `-L` search order. On Windows, validate the CMake
installed route; do not claim a reviewed pkg-config consumer run there.
