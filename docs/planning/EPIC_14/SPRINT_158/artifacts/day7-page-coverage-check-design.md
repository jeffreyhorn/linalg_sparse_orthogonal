# Day 7 Page Coverage Check Design

## Scope

Day 7 designs the generated API page-coverage guard selected by the Day 6
guarded local-only publication decision.

The guard verifies that local Doxygen output under `docs/api/html/` contains
expected pages for checked-in public headers. It does not publish generated
HTML, commit ignored output, or change source/header behavior.

## Selected Guard Shape

| Design field | Decision |
| --- | --- |
| Primary owner | New focused script: `scripts/check_api_docs_coverage.py`. |
| Command wrapper | New Make target, proposed as `api-docs-coverage`. |
| Combined generation/check target | Optional Day 8 addition, proposed as `docs-check` if scope remains focused. |
| Source set | Checked-in public headers matching `include/*.h`. |
| Generated output path | `docs/api/html/`. |
| Required page type | Doxygen header reference page for each checked-in public header. |
| Supplemental page type | Doxygen source page for each checked-in public header. |
| Generated version-header handling | Separate policy row; not an expected checked-in header page. |
| Publication status | Local-only guard result; not source-controlled or hosted evidence. |

Script ownership is preferred because the header-to-page mapping and missing
page reporting are easier to test and review in one focused file. A Make target
keeps the maintainer command discoverable next to `make docs`.

## Inputs

| Input | Required behavior |
| --- | --- |
| Repository root | Default to the script parent repository root or accept an explicit `--root`. |
| Public header directory | Default `include/`; inspect only direct `*.h` files. |
| Generated HTML directory | Default `docs/api/html/`; do not create it. |
| Exclusions | None for checked-in `include/*.h` under current Day 3 policy. |
| Version-header policy | Do not require `sparse_version.h` because it is generated under build/install paths from `include/sparse_version.h.in`. |

## Expected Page Mapping

The Day 2 and Day 3 generated tree shows Doxygen's current page naming for
headers:

| Source filename rule | Generated filename rule |
| --- | --- |
| `_` in the header basename | becomes `__` |
| `.h` extension | becomes `_8h` |
| reference page suffix | `.html` after applying Doxygen escaping |
| source page suffix | `_source.html` after applying Doxygen escaping |

Examples:

| Header | Reference page | Source page |
| --- | --- | --- |
| `include/sparse_lu_csr.h` | `docs/api/html/sparse__lu__csr_8h.html` | `docs/api/html/sparse__lu__csr_8h_source.html` |
| `include/sparse_types.h` | `docs/api/html/sparse__types_8h.html` | `docs/api/html/sparse__types_8h_source.html` |
| `include/sparse_vector.h` | `docs/api/html/sparse__vector_8h.html` | `docs/api/html/sparse__vector_8h_source.html` |

Day 8 should implement this mapping directly rather than hard-coding the 18
current header names.

## Pass/Fail Behavior

| Condition | Result | Diagnostic |
| --- | --- | --- |
| `docs/api/html/` is missing | Fail | Print the missing directory and suggest running `make docs`. |
| `docs/api/html/index.html` is missing | Fail | Print the missing index path and suggest rerunning `make docs`. |
| A checked-in public header lacks its reference page | Fail | Print source header and expected reference page path. |
| A checked-in public header lacks its source page | Fail unless Day 8 explicitly marks source pages supplemental | Print source header and expected source page path. |
| Extra generated pages exist | Pass | Extra pages are allowed because Doxygen emits structs, globals, navigation, CSS, JS, and helper pages. |
| `sparse_version` page is absent | Pass | This is expected under the Day 3 generated version-header policy. |
| All expected pages exist | Pass | Print header count and page count summary. |

Recommended Day 8 behavior: make source pages required as well as reference
pages. Day 3 already observed all 18 source pages, so requiring them tightens
the guard without adding new Doxygen policy.

## Generated Version-Header Policy

`sparse_version.h` is installed for package consumers, but it is generated by
Make/CMake from `VERSION` and `include/sparse_version.h.in`. It is not checked
in as `include/sparse_version.h`, and current `Doxyfile` input does not include
build directories.

The guard should therefore:

- not include `include/sparse_version.h.in` in the checked-in public-header
  page set;
- not require a generated `sparse__version_8h.html` page;
- print a short note or keep documentation stating that generated version
  metadata is handled by the policy row, not by page coverage;
- fail only if checked-in `include/*.h` pages are missing.

## Freshness And Local-Only Semantics

The guard validates the local generated tree it sees. It does not prove that
the tree was regenerated moments before the check unless paired with `make
docs`.

Day 8 should therefore expose or document two usages:

```sh
make docs
make api-docs-coverage
```

or, if a combined wrapper is selected:

```sh
make docs-check
```

The command result may support a local freshness claim for the current
branch/run, but it does not make `docs/api/html/` source-controlled, hosted, or
release evidence.

## Validation Expectations

| Touched surface | Required validation |
| --- | --- |
| New Python script | Run the script against the current generated tree; include at least one deterministic negative-path design note or self-check if practical. |
| New Make target | Run the target; ensure it fails through the script's nonzero exit status. |
| Public docs updated later | `git diff --check`; claim-sensitive scan. |
| Public headers changed later | `make format && make lint && make test`; `make docs`; page-coverage guard. |
| Generated HTML | Keep ignored; verify it is not staged. |

## Day 8 Implementation Plan

1. Add `scripts/check_api_docs_coverage.py`.
2. Add `api-docs-coverage` Make target that invokes the script.
3. Prefer adding a focused `docs-check` target only if it does not disrupt
   existing `docs` behavior.
4. Run `make docs`.
5. Run the new coverage guard.
6. Record whether the guard reports 18 checked-in public headers, 18 reference
   pages, and 18 source pages.
7. Confirm `docs/api/` remains ignored and no generated HTML is staged.

## Completion Check

- Coverage expectations are deterministic.
- Missing public-header pages can be reported with concrete source and output
  paths.
- Generated `sparse_version.h` behavior is explicitly separated from checked-in
  public-header coverage.
- The design preserves local-only generated HTML semantics.
