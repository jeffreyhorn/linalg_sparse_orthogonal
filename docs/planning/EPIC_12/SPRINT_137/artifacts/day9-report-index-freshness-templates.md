# Sprint 137 Day 9 - Report Index & Freshness Templates

## Purpose

Day 9 defines the report-index and stale-report contracts Sprint 141 will
implement. The templates preserve row meaning across evidence families instead
of flattening benchmark, sentinel, guardrail, coverage, dead-code, package,
corpus, and oracle outputs into one ambiguous pass/fail table.

These templates support freshness, traceability, and interpretation. They do
not turn generated reports into release proof, broad correctness proof,
coverage completeness, portable performance proof, package parity proof, or
state-of-the-art evidence.

## Shared Report Metadata Template

Every normalized report-index row should include this minimal metadata. Family
specific values may live in separate files, but index rows must carry enough
context to interpret freshness and support tier.

| Field | Required | Meaning |
| --- | --- | --- |
| `report_row_id` | Yes | Stable row identifier unique within the normalized index. |
| `report_family` | Yes | `canonical_benchmark`, `performance_sentinel`, `large_matrix_guardrail`, `deadcode`, `coverage`, `package_proof`, `corpus_fixture`, `oracle`, `runtime_backend`, or `hosted_ci`. |
| `row_kind` | Yes | `measurement`, `threshold_gate`, `structural_gate`, `package_gate`, `oracle_comparison`, `coverage_artifact`, `triage`, `skip`, `defer`, or `metadata_only`. |
| `row_subject` | Yes | Benchmark name, fixture key, package mode, CI job, script name, or artifact name. |
| `artifact_path` | Conditional | Relative path to the generated artifact when one exists. |
| `generator_command` | Yes | Exact command or workflow step that produced the row. |
| `source_commit` | Yes | Git commit used to generate the row. |
| `source_branch` | Yes | Branch name, tag, or `detached`. |
| `generated_at_utc` | Yes | UTC timestamp when the artifact was produced. |
| `platform` | Yes | OS, architecture, and hosted/local context when available. |
| `compiler` | Conditional | Compiler and version when relevant. |
| `configuration` | Yes | Build flags, package mode, OpenMP/backend state, optional-data state, or report mode. |
| `support_tier` | Yes | `reviewed_linux`, `reviewed_macos`, `reviewed_windows`, `supplemental`, `local_only`, `optional_data`, or `staged`. |
| `status` | Yes | `pass`, `fail`, `skip`, `defer`, `xfail`, `metadata_only`, or `unknown`. |
| `status_reason` | Conditional | Required for non-pass and metadata-only rows. |
| `row_meaning` | Yes | One-sentence statement of what the row means. |
| `claim_scope` | Yes | One-sentence statement the row may support. |
| `non_claims` | Yes | Explicit claims this row does not support. |
| `freshness_status` | Yes | `fresh`, `stale`, `unknown`, or `not_applicable`. |
| `freshness_reason` | Conditional | Required when freshness is not `fresh`. |

## Freshness Fields

Freshness checks must compare the report row against the repository state and
the command contract. A stale row is stale evidence, not a numerical failure.

| Field | Required | Meaning |
| --- | --- | --- |
| `expected_source_commit` | Yes | Commit expected by the freshness check, usually current `HEAD` for regenerated artifacts. |
| `observed_source_commit` | Yes | Commit recorded in the report row. |
| `expected_command` | Yes | Maintained command expected to generate this report family. |
| `observed_command` | Yes | Command recorded in the row. |
| `expected_platform_class` | Yes | Platform class required for the row, such as `linux`, `macos`, `windows`, `any_local`, or `hosted_only`. |
| `observed_platform` | Yes | Platform recorded in the row. |
| `expected_compiler_class` | Conditional | Compiler family or version class when the row is compiler-sensitive. |
| `observed_compiler` | Conditional | Compiler recorded in the row. |
| `expected_configuration` | Yes | Expected build/package/backend/optional-data configuration. |
| `observed_configuration` | Yes | Configuration recorded in the row. |
| `max_age_policy` | Yes | `same_commit`, `same_branch`, `time_window`, `manual_review`, or `not_applicable`. |
| `generated_at_utc` | Yes | Timestamp recorded in the row. |
| `freshness_status` | Yes | `fresh`, `stale_commit`, `stale_command`, `stale_platform`, `stale_compiler`, `stale_configuration`, `stale_time`, `unknown`, or `not_applicable`. |
| `freshness_action` | Yes | `accept`, `regenerate`, `manual_review`, `ignore_optional_skip`, or `defer`. |

## Stale-Report Check Expectations

Sprint 141 stale-report automation should implement these checks where the row
family provides the required fields:

1. **Commit check:** rows with `max_age_policy=same_commit` are stale when
   `observed_source_commit` differs from `expected_source_commit`.
2. **Command check:** rows are stale when the generator command no longer
   matches the maintained command for the report family.
3. **Platform check:** reviewed platform rows are stale or invalid when the
   observed platform does not match the required platform class.
4. **Compiler check:** compiler-sensitive rows are stale when the observed
   compiler does not match the expected compiler class.
5. **Configuration check:** rows are stale when build flags, package mode,
   backend state, OpenMP state, optional-data state, or report mode differ from
   the expected configuration.
6. **Time-window check:** rows with time-based freshness are stale after the
   configured window, but this is a report freshness failure only.
7. **Optional-data check:** skipped optional rows remain valid skip-policy
   evidence only when their skip reason and optional-data state are current.

## Failure Semantics

| Failure class | Meaning | Required handling |
| --- | --- | --- |
| `stale_commit` | Report was generated from a different commit than the one being claimed. | Regenerate before using for claims. |
| `stale_command` | Report was generated with an old or different command. | Regenerate with the maintained command or update the row contract. |
| `stale_platform` | Report platform does not match the support-tier claim being made. | Do not use row for platform promotion. |
| `stale_compiler` | Compiler metadata does not match the required compiler class. | Regenerate or demote to supplemental/local evidence. |
| `stale_configuration` | Build, package, backend, OpenMP, optional-data, or report configuration differs. | Regenerate under expected configuration before comparing rows. |
| `stale_time` | Row exceeded its configured age window. | Regenerate or mark as historical. |
| `missing_artifact` | Index row points to an artifact that is absent. | Treat as report integrity failure. |
| `malformed_row` | Required metadata field is absent or invalid. | Treat as report integrity failure. |
| `unsupported_family` | Report family cannot yet provide safe metadata. | Keep family out of normalized gate and record deferral. |
| `optional_skip_current` | Optional data remains unavailable and the skip row is current. | Keep as skip-policy evidence only, not pass evidence. |

## Normalization Eligibility

| Report family | Eligibility | Required before normalization |
| --- | --- | --- |
| Canonical benchmark report | Eligible | Add shared metadata fields while preserving raw CSV artifacts and threshold-free interpretation. |
| Performance sentinels | Eligible with care | Preserve thresholded versus non-thresholded row kinds and local-only interpretation. |
| Large-matrix guardrails | Eligible | Preserve structural/test/report row kinds and supplemental skip/report rows. |
| Dead-code report | Eligible | Preserve bucket/disposition semantics and public-review boundaries. |
| Coverage report | Metadata-only initially | Normalize artifact/freshness fields only; do not translate coverage percent into behavioral completeness. |
| Package proof logs | Metadata-only initially | Normalize command/freshness/status fields while preserving raw logs for detail. |
| Corpus fixture manifest | Eligible after Sprint 138 | Use Day 8 fixture template as the row source. |
| Oracle rows | Eligible after Sprint 138 | Use Day 8 oracle template and failure interpretation rules. |
| Runtime/backend sentinel rows | Eligible after Sprint 142 | Requires runtime/backend precedence and sentinel semantics first. |
| Hosted CI job summaries | Deferred unless run metadata is available | Do not infer hosted evidence from local planning artifacts. |
| Ad hoc local benchmark output | Not eligible | Lacks stable command, support tier, and row semantics. |
| Historical prose-only report notes | Not eligible | Lacks machine-checkable metadata and freshness fields. |

## Report Non-Claim Rules

- A normalized row means the row is interpretable, not that the project is
  release-ready.
- A fresh row means the metadata matches the expected command, commit,
  platform, compiler, and configuration policy; it does not mean the measured
  result is good.
- Benchmark and sentinel rows remain local evidence unless a later sprint adds
  cross-platform reproducibility and explicit thresholds.
- Coverage rows remain supplemental line-coverage evidence and do not prove
  behavioral completeness.
- Dead-code rows remain triage evidence until public API and owner review make
  a removal decision.
- Package proof rows prove only the selected package mode, support tier, and
  downstream command path represented by that row.
- Oracle rows prove only fixture-local behavior under their tolerance and
  support tier.
- Skipped optional-data rows prove only skip-policy behavior.
- Hosted CI rows can support platform promotion only when the run metadata,
  expected command, support tier, and failure semantics are present.

## Sprint 141 Implementation Handoff

Sprint 141 should implement report normalization in this order:

1. Define the normalized index storage path and row serialization format.
2. Add shared metadata fields to eligible report families without changing
   their raw family-specific artifacts.
3. Add freshness checks for commit, command, platform, compiler,
   configuration, generated time, and artifact presence where metadata exists.
4. Keep coverage and package proof rows metadata-only until richer row
   semantics are implemented.
5. Exclude ad hoc and historical prose-only reports from the normalized gate.
6. Document every excluded family with an owner, blocker, and promotion gate.
7. Update maintainer/report docs so normalized indexes are not interpreted as
   release, correctness, coverage-completeness, or performance proof.
