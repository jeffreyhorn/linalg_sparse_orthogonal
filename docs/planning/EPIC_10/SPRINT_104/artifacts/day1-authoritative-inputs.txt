Sprint 104 project-plan goal
----------------------------

Establish a durable backend and runtime contract for builtin dense kernels,
optional acceleration, OpenMP behavior, and bounded local regression evidence.

Sprint 104 project-plan items
-----------------------------

1. Backend Consumer Audit
   - Profile dense backend consumers, fallback paths, and optional acceleration
     points across direct and decomposition families.
   - Estimate: 20 hours

2. Runtime Contract Design
   - Define runtime expectations for builtin kernels, optional backends,
     OpenMP, nested parallelism, and observability.
   - Estimate: 30 hours

3. Backend Descriptor Batch
   - Refine or extend the backend descriptor and selection surface without
     weakening builtin fallback truth.
   - Estimate: 32 hours

4. OpenMP and Threading Cleanup
   - Reduce confusing thread-local/global override behavior and document
     remaining runtime controls.
   - Estimate: 24 hours

5. Performance Sentinel Batch
   - Add bounded local regression sentinels for hot paths without claiming
     portable timing superiority.
   - Estimate: 22 hours

6. Benchmark Reporting Alignment
   - Reconcile benchmark docs, scripts, and artifacts with the refined
     backend/runtime contract.
   - Estimate: 18 hours

7. Validation and Closeout
   - Run required checks, compare benchmark artifacts, and close Sprint 104.
   - Estimate: 22 hours

Sprint 104 expected deliverables
--------------------------------

- clearer backend descriptor and runtime selection contract
- documented builtin fallback and optional acceleration behavior
- bounded local performance regression sentinels
- benchmark wording aligned with actual evidence
